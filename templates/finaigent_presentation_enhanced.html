⚙️ Query Processing Flow: Step-by-Step

1
User Input (ANY Language)
User asks in their native language (e.g., Tamil: "யாரோ என் OTP கேட்கிறார்கள்")
2
Automatic Language Detection
System identifies: Tamil detected → Prepare for translation pipeline
3
Dynamic Translation to English
"யாரோ என் OTP கேட்கிறார்கள்" → "Someone is asking for my OTP"
4
Finance Domain Validation
Keywords: "someone", "asking", "OTP" → Flagged as potential scam query ✅
5
TF-IDF Vectorization
Convert English query to numerical vector for similarity matching
6
kNN Retrieval (Cosine Similarity)
Search English knowledge base → Find top 5 most similar documents about OTP scams
7
RAG Prompt Construction
Combine: Retrieved English context + User query + Safety constraints → Send to LLM
8
LLM Generation (Google Gemini)
Generate grounded English response: "Never share OTP with anyone. This is a scam..."
9
Dynamic Translation Back to Tamil
"Never share OTP..." → "OTP யாருடனும் பகிர வேண்டாம். இது மோசடி..."
10
Response Delivery
Display safe, accurate answer to user in Tamil (or ANY language they used) 🎯

⚠️ Current Limitations & Challenges

🔧 Technical Limitations

  • Translation Dependency: Quality varies by language pair
  • Cultural Nuances: Some idioms may not translate perfectly
  • Internet Required: Translation APIs need connectivity
  • TF-IDF Limits: Weaker semantic understanding than embeddings

🌐 Deployment Challenges

  • Regional Dialects: Standard language vs. local variants
  • Low-resource Languages: Limited translation training data
  • Trust Building: Users skeptical initially
  • Connectivity: Rural areas with poor internet

💡 Mitigation Strategies

For Translation Quality:

  • Use multiple translation APIs (fallback)
  • Post-editing by native speakers
  • Build glossary of financial terms

For Deployment:

  • Offline mode with cached translations
  • SMS fallback for text-only queries
  • Community workshops in local languages
